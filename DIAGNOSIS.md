# Сравнение переданных версий

Все пять агентов и четыре patch-файла просмотрены; исторические патчи не запускаются.

| Файл | Наблюдение и решение |
|---|---|
| 01 clean | ALSA/aplay, необязательный Spotify, reconnect-loop. Полезна схема spotify_command; прямой ALSA обходит AEC, не используем его для обычного вывода. |
| 02 initial | Непрерывный Pulse capture, очередь и flush, выход 24k mono. Ещё только inline parts; здесь это пропускало аудио. |
| 03 fixed | Добавлен 24→48 и stereo. Общий путь 24k использует повтор отсчётов; корректная длительность, но без интерполяции. |
| 04 response_data | Правильный приоритет response.data, fallback inline, повтор receive в одной сессии. Убрана постоянная печать каждого чанка. |
| 05 current | Wake по транскрипции и 20s окно. Стартовая основа; исправлены drain-lock, скрытый prewake-buffer, границы PCM и подавление interruption. |
| patch_gemini_assistant | Исправлял mono/stereo размер буфера, непрерывный mic и Spotify. Микрофон через ALSA без AEC для итоговой версии не используем. |
| patch_gemini_live_loop_echo | Правильный внешний while вокруг receive; расширение VAD prefix само по себе не устраняет эхо. |
| patch_fix_audio_bargein | Полезно не терять транскрипцию из того же interruption-события. HIGH VAD и PCM mono 48k не соответствуют последнему контракту. |
| patch_native_48k_stereo | Дублирование mono в L/R без 24→48 resampling даёт ускорение при исходных 24k; не применять. |

Пути root из задания заменены на home tusone по прямому запросу пользователя.
AEC остаётся у voice. Launcher больше не вызывает отсутствующий calibration-скрипт.
PowerShell теперь развёртывает целый комплект, а не заменяет root-файл и запускает
root-агент. Нет копирования ключей или удаления старых root-файлов.

Локальная проверка выполнялась на Linux x86_64/Python 3.12 с google-genai 2.29.0.
Проверены SDK config, PCM, wake, receive и flush на моделируемых событиях;
это не подтверждение доступности модели, ARM-сборки, звука, AEC или Spotify на плате.
PowerShell в этой среде отсутствует: скрипт проверен чтением, Windows-запуск не выполнен.

## Обновление после проверки на плате

Пользователь подтвердил подключение, аудиотесты и получение input transcription,
но обычные приветствия не вызывали ответа. Версия 05 требовала wake-фразу и в
системной инструкции, и в локальном output gate; неверная транскрипция дополнительно
делала распознавание имени ненадёжным. Теперь continuous duplex — default,
SLAVIK_WAKE_ENABLED=1 возвращает прежний режим. Добавлена русская языковая
инструкция; качество серверной транскрипции не подтверждено новым запуском.
Один WebSocket, непрерывная передача микрофона и PCM/AEC маршруты сохранены.

Пользователь уточнил UX: wake-режим возвращён по умолчанию. После обращения
окно команд 20 секунд, продление только в активном окне, затем тишина до нового
обращения. Непрерывные capture/WebSocket и русская инструкция сохранены.

## Калибровка, RU/EN и Spotify

Default timeout сокращён до 5 секунд. Разрешение конкретной пользовательской
команды сохраняется до конца её хода, чтобы задержка модели/API не отбрасывала
ответ; неадресованная речь после истечения окна не открывает новый ход.
Найдено language_codes в SDK 2.29.0 — поле является hints, не allowlist языков.
Добавлен fallback только при явном Unknown name language_codes в начальном setup.
DSP входа: фиксированный right/16k, HP60Hz, измеренный gain и peak headroom.
Не добавлен noise gate, способный подавлять барж-ин/слабую речь.

Spotify bridge написан заново (старого в архиве нет), PKCE без Client Secret.
Официальные исходники Raspotify inspected at d0250f176ad58836fb89a6ffb1246d23389549d6,
включая signed-by apt repo и pulseaudio build feature. Проверен upstream
librespot Pulse backend: параметр device передаётся как sink. Connect installer
использует пакетный /usr/bin/librespot и отдельную службу voice с AEC sink.
Официальные страницы Spotify docs и GitHub release API ответили 403 в этой среде;
OAuth и account permissions остаются непроверенными до входа пользователя.
Никакие credentials/службы реальной платы здесь не предоставлены.
