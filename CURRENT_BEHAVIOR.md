# Славик: текущее поведение

Основной режим — прямой `gemini-3.1-flash-live-preview`, постоянный микрофон и Live
websocket. Отдельный медленный WAV-ASR в обычном запуске не используется.
Эта страница заменяет прежние инструкции про строгое имя для каждой фразы,
5-секундное ожидание, принудительный физический выход100% и старую миграцию уровней.

## Обновить существующую установку

Остановить Славика через Ctrl+C, затем от tusone:

```bash
cd ~/slavik
git pull --ff-only
bash install-linux.sh
./start-gemini-assistant.sh --asr-engine live --followup-seconds 3 --mic-enhancement speex
```

В этом обновлении меняются root-owned аудиомост и music_duck.py: install-linux.sh
копирует их с резервной копией и устанавливает libspeexdsp1. Перезапуск PipeWire не нужен.
`--asr-engine live` имеет приоритет над старым SLAVIK_ASR в .env. Обычный запуск
без флагов также выбирает Live и окно3s, если новые настройки явно не менялись.
Старые SLAVIK_AWAKE_SECONDS/SLAVIK_FOLLOWUP больше не задают окно; актуальная
переменная SLAVIK_FOLLOWUP_SECONDS=3. CLI --followup-seconds0 включает строгий режим.

## Обращение, продолжение и перебивание

- Одно имя («Славик», «Эй Славка») при активной музыке убирает только музыкальный
  поток до нуля и открывает ровно3s ожидания команды без голосового подтверждения.
  Трек не ставится на паузу. Нет команды — прежняя громкость возвращается.
  Есть команда — музыка остаётся убранной до начала ответа Славика, а не возвращается
  на первом фрагменте транскрипции. Во время ответа обычное приглушение около6dB.
  Ожидание результата без ответа ограничено30s с последнего принятого фрагмента.
- Три секунды дают время начать команду. Локальный WebRTC VAD после обращения
  удерживает уже начатую речь и даёт1.5s на приход её транскрипции; дополнительное
  удержание ограничено15s против ложного срабатывания. VAD не будит ассистента
  и не даёт права выполнять инструменты: авторизация остаётся у обращения/транскрипции.
  Микрофон продолжает непрерывно отправляться в Live, PCM не режется по этому таймеру.
- Мост подтверждает duck:listen после применения уровней; окно3s начинается по
  подтверждению, включая случай медленной команды Pulse. Это подтверждение API,
  не измерение акустической задержки колонки. Debug-events показывают
  music_mode_requested/applied и input_transcript для дальнейшей диагностики.
- Без музыки одно имя допускает короткое «Я слушаю». Наличие устройства Spotify
  или поставленный на паузу поток не считается играющей музыкой. Аудиомост проверяет
  corked/mute/уровни Spotify примерно раз в секунду и отдаёт состояние приложению.
  При выключенном SLAVIK_MUSIC_DUCK/недоступном мосте статус неизвестен: безусловного
  молчаливого ожидания нет. Мост должен быть обновлён через install-linux.sh.
- После обращения с просьбой и каждого озвученного ответа — полные3s для следующей реплики
  без имени. Таймер начинается при окончании звука, включая очередь и Pulse tail,
  а не при завершении генерации. Новая принятая реплика продлевает окно.
  Отфильтрованное эхо во время ответа больше не лишает следующего окна: после
  окончания звука оно открывается заново, а разрешение на самостоятельный ответ — нет.
  Завершение отменённого старого ответа не перезапускает истёкшее ожидание после имени.
- Одно открытое окно не позволяет модели заговорить самой: требуется свежая реплика.
  После истечения3s снова нужно имя. Музыкальная команда также оставляет окно3s.
- Имена Славик/Славка/Слава/Славуха/Славчуха в любой части фразы. Добавлены Слайк,
  Слайка, Слайвик, Слаек, Флаек, Свавик, Славян, Славчик, Сварик, латинские варианты.
  Близкие написания и фонетический каркас сравниваются с именем, более слабые
  совпадения требуют контекста команды/приветствия. Распознанный «флаг, какая погода»
  может быть обращением. Это намеренно широкий фильтр, возможны ложные пробуждения.
- Модель также может подтвердить обращение инструментом wake_assistant по аудио
  при свободном выходе, если текст не отвергнут как эхо. SLAVIK_AUDIO_WAKE=0 отключает
  этот дополнительный способ. Любой музыкальный tool-call сам по себе не будит.
- Во время озвучки в активном диалоге принимается новая реплика без имени,
  если она не совпала с недавним ответом. Она очищает старую очередь звука.
  Вне активного диалога нужно обращение. Остаток старой генерации не воспроизводится, новый запрос сохраняется
  до её завершения. Серверный interrupted сам по себе не останавливает pacat.
  NO_INTERRUPTION сохраняется: фон/эхо не прерывают генерацию автоматически.
- Короткий ответ на явное уточнение инструмента принимается в окне без имени,
  даже если слова совпадают с частью вопроса («В Узбекистане»). Обычное эхо недавнего
  ответа отсеивается. После выявленного эха окно закрывается до нового имени, чтобы следующая
  ошибочная транскрипция эха не запустила разговор с самим собой. Во время озвучки
  фильтруются также короткие повторы собственных слов. Это текстовый фильтр:
  он может ошибаться при неверной транскрипции; акустический AEC всё ещё необходим.

В Gemini по-прежнему идёт один выбранный AEC-канал. Калибровка сравнивает оба поSNR,
при разнице менее3dB оставляет правый. Это не beamforming и не новый акустический AEC.
Расширение триггеров не восстанавливает слова, потерянные при перегрузе/помехах.

## Звук и громкость

Физический Pulse-выход платы теперь60%, AEC master остаётся100%, обычная громкость меняет музыку,
«говори тише/громче» — только голос. Голос стартует40%. Приглушение Spotify около6dB
во время адресованной обработки/ответа. Только после одного имени при музыке
музыкальный поток убирается полностью на3s ожидания начала команды;
при начатой команде — до начала ответа/таймаута, как описано выше.
После обычного ответа дополнительного3s хвоста приглушения нет.
После фактического окончания ответа музыка возвращается сразу, окно продолжения
ещё3s открыто. Headphone/Speaker больше не форсируются в100%/+6dB: положительное
аналоговое усиление ограничивается0dB, уже ослабленный рабочий выход сохраняется,
нулевой восстанавливается. Playback остаётся100%, PCM включён. После изменения
микшера physical60% применяется повторно, чтобы Pulse/ALSA не разошлись. Capture,
boost и профиль микрофона автоматически не меняются. Это снижение уровня, не
доказательство устранения перегруза или исправления акустики.

Очередь PCM теперь вмещает до120s (~23MB при48k stereo), вместо прежних10.24s.
При заполнении producer ожидает свободное место, не падает с ложным сообщением
«audio device too slow». Большие PCM порции обрабатываются частями с передачей
управления захвату/приёмнику. Это программная очередь, quantum480 не увеличивался.
Обращение по имени может очистить очередь; данные прежнего поколения отбрасываются.
Длиннее120s при полном буфере приёмник ждёт writer: это ограничение backpressure,
а не гарантия бесконечной буферизации на плате с484MB.

## Опытный шумодав и автоматическое усиление

`--mic-enhancement speex` (либо SLAVIK_MIC_ENHANCEMENT=speex) включает нативный
SpeexDSP ПОСЛЕ WebRTC AEC, выбранного канала и прежнего DSP. Это шумодав -15dB
и ограниченный AGC: цель4000, увеличение6dB/s, уменьшение30dB/s, максимум+12dB.
16k mono, кадры20ms, без отдельного облачного ASR и без нового ресемплинга.
На fixed-point сборке без AGC остаётся шумодав, об этом явно пишет стартовый лог.
Это определение/обработка речи, не обучение личности владельца и не голосовой отпечаток.
Остаточное эхо музыки всё ещё должен убирать AEC по опорному сигналу; один шумодав
не решает эту задачу. Двойная обработка может съедать тихие согласные, поэтому режим
опытный: default=off, явный CLI имеет приоритет над .env. Для сравнения повторить
тот же запуск с `--mic-enhancement off`. Перекалибровка автоматически не выполняется.

В облаке собран upstream SpeexDSP1.2.1, commit1b28a0f61bc31162979e1f26f3981fc3637095c8,
в /workspace/slavik-review/libspeexdsp-test.so (для тестов SLAVIK_SPEEX_LIBRARY).
Настоящий C-код проверен на тишине, непрерывности кадров, контролях AGC и синтетическом
шуме. RMS шума после адаптации289→55.7, 4s сигнала обработаны за~0.025s на облачном
x86_64. Это не тест речи, распознавания, ARM-производительности или максимальной колонки.
На плате используется системный пакет libspeexdsp1 из подписанного apt-репозитория.

## Погода и новости

Ташкент по умолчанию означает Узбекистан и использует координаты города напрямую,
без вопроса о российских одноимённых населённых пунктах. Если явно указана другая
страна, она учитывается. Погода — свежий запрос Open-Meteo, текущие условия/прогноз,
не догадка модели. Город меняется голосом либо SLAVIK_CITY. Country передаётся отдельно.

Для новостей web_search(kind=news) сначала получает Google News RSS: заголовки,
даты публикаций, издателей и ссылки. Обычно запрос ограничен последней неделей,
если пользователь/запрос не задаёт период. Это заголовки, не прочитанные полные статьи.
Если RSS недоступен, используется Google Search через доступную Flash-модель.
Общий поиск также выбирает модель из каталога API, старый фиксированный2.5Flash
не является дефолтом. При404/503/неподдерживаемом grounding пробуется другая модель;
403/429 не обходятся. Ошибка содержит код для диагностики, источники не выдумываются.
Запросы поиска/новостей происходят только по просьбе, не при старте Live.

В облаке RSS live-check получил ошибку сетевого proxy, ключа Gemini нет: реальные
погода/поиск/новости на аккаунте пользователя требуют приёмки. Наличие тестов
с RSS/API fixtures не означает доступность источника с платы.

Обычные биографии, объяснения и известные мемы не требуют обязательного поиска.
При429 инструмент сообщает, что недоступен именно поиск; модель может ответить
стабильной известной частью, не придумывая свежих фактов. В инструкцию добавлены
Меллстрой/Молстрой/Mellstroy — Андрей Бурим. Голос Kore сохранён.

## Локальный лор и редкие отсылки

Переданный20октября разбор сохранён в meme_lore.json:23 раздела, персонажи, связи,
сеттинги и условная хронология. Включены Мама-птица/птенцы, Ч/Друн/Фог/Мурино,
темщики/общага/банька/армия/поезд, Молочное/паучности/трамвай/Сметанное/Кефирное,
Мытищи/Артур/Арина/Мойдодыр/районы, Элджеевка, Куки/котость, смены, Баба Чай,
Славчуха, мини-сезоны/DLC. Новый локальный инструмент meme_lore возвращает обзор
или до6 подробных совпадений, без сети, Google Search и отдельной модели ASR.
Полный справочник не вставляется в каждую Live-сессию; детали берутся по запросу.

Источник — пересказ пользователя из другого чата, не независимая проверка веб-сайтов.
Фанон не выдаётся за реальные события или единый канон; неизвестные биографии
Славчухи/Бабы Чай и детали DLC не дописываются. Слухи о реальном задержании не
становятся подтверждённой новостью. Справочник — данные, не инструкции извне.
Инструкция модели просит редкие шутки к месту, ориентир — не чаще одной на6
содержательных ответов. Это инструкция генерации, не строгий программный счётчик.
В подтверждениях команд, ошибках и ожидании имени шуток быть не должно.
«Выдай мемчик»/«кинь прикол» теперь отдельный mode=joke: инструмент возвращает одну
короткую собственную шутку по фанону, без overview/entries и без немедленного повтора.
spoken_response не является цитатой Меллстроя. Снимок текущей просьбы передаётся
инструменту, чтобы просьба о мемчике не превратилась в обзор даже при ошибочном mode
от модели. В ответе — только реплика, без расшифровки/вопроса. «Объясни мем» и
«расскажи про мем» продолжают получать справку. Соблюдение формата самой Live-моделью
нужно проверить в реальном разговоре.
Примеры вопросов: «Славик, кто такой Фог?», «А чем Мытищи отличаются от Мурина?»,
«Расскажи про Маму-птицу», «Кто такая Баба Чай?». Последние вопросы можно продолжить
без имени в течение3s после ответа. Реальная речь/соблюдение стиля требуют приёмки.

## Spotify

Connect-плеер, службу и исправление ручного выбора не меняем. Следующий/предыдущий,
пауза/продолжение, музыка по названию/исполнителю/плейлисту и подборки остаются.
Статусы инструмента accepted/confirmed/unknown/failed и spoken_response различаются;
повтор одного call-id не выполняет команду дважды. Актуальный трек/позиция черезstatus.
`--asr-test` ТОЛЬКО распознаёт тестовую фразу и никогда не запускает Spotify.

## Экспериментальный ASR и диагностика

Отдельный WebRTC VAD + Gemini WAV-ASR доступен только через --asr-engine gemini;
добавляет запросы, задержку и отдельную зависимость от доступности моделей. Его
диагностика --asr-test не нужна для обычного Flash Live. При503 тот же PCM повторяется,
затем пробуются до2 резервных моделей, максимум60s; в исполнение попадает только
успешно распознанная адресованная просьба. Это не специализированный новый ASR.

Для акустики: при остановленном Славике --aec-test / --record-mic при музыке и речи.
AEC-тест теперь читает три потока: физические микрофоны, обработанный AEC и
voice_aec_sink.monitor (опора воспроизведения). Показатель playback_reference
при играющей музыке не должен оставаться нулевым. Это измерение уровней, без
выравнивания задержки: оно не доказывает корреляцию, ERLE или разборчивость.
--diagnose выводит aec_reference с проверкой маршрутов активных потоков и пары
source/sink. Проверку голоса делать во втором SSH во время ответа, музыку оставить
включённой. Новый pacat помечен SlavikVoice. Предупреждения о потоке, обходящем AEC,
нужно разобрать до настройки усиления.

Вычитание опорного сигнала с адаптацией задержки и акустического пути уже выполняет
установленный WebRTC AEC. Новый Python-вычитатель не добавлялся, AEC-конфигурация
платы в репозитории отсутствует. Физический выход снижен до60%; 48k stereo и quantum480 сохранены.
--record-mic сохраняет физический stereo, AEC до DSP и выбранный канал послеDSP
только по явной команде локально. Для артефактов/ERR — bash trace-audio.sh во время
проблемы. Не поднимать quantum до960/1024 для прежнего WebRTC AEC.

Текущая программная приёмка: 169 тестов с нативной SpeexDSP. На плате проверить3s продолжение, обращение
во время ответа, длинную озвучку без crash, Ташкент без уточнения и новости Tesla.
Слышимость при максимальной колонке и качество AEC этой правкой не доказаны.
