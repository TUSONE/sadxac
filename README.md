# Славик — чистая установка от tusone

**Текущая установка и поведение:** [CURRENT_BEHAVIOR.md](CURRENT_BEHAVIOR.md). Там описаны физический выход60%, AEC100%, ожидание после имени только при музыке, окно3s, локальный лор и текущая установка. При расхождении со старыми разделами ниже используйте эту страницу.

Для пробы прямого микрофона без входного AEC и локального RNNoise см.
[порядок сравнения](CURRENT_BEHAVIOR.md#прямой-микрофон-и-rnnoise-опытный-режим).

Актуальное состояние, последний отчёт о сбоях и порядок дальнейшей работы: [PLAN_NEXT.md](PLAN_NEXT.md).

Это собранная версия на основе переданных 04/05, с исправлениями очереди,
прерывания и преобразования PCM. На компьютере разработчика пройдены локальные
тесты; Gemini, Banana Pi, WM8960 и реальное AEC здесь не проверены.

## Получить из GitHub

С Windows (нужен установленный Git):

```powershell
git clone https://github.com/TUSONE/sadxac.git
cd sadxac
powershell -NoProfile -ExecutionPolicy Bypass -File .\install_slavik_agent.ps1
```

Можно установить прямо на Banana Pi, подключившись как `tusone`:

```bash
git clone https://github.com/TUSONE/sadxac.git ~/slavik
cd ~/slavik
bash install-linux.sh
```

Если `~/slavik` уже существует, сначала остановите агент и сохраните папку
под другим именем. Не клонируйте поверх существующей установки.
После установки добавьте ключ и выполните проверки ниже.

## Установка с Windows

1. Распакуйте архив в отдельную папку. Сохраните старые файлы `/root`.
   Сначала остановите старый агент через Ctrl+C в его терминале. Если он работает
   как служба, остановите именно известную службу. Два агента одновременно не запускайте.
2. В PowerShell откройте распакованную папку:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\install_slavik_agent.ps1
   ```

   Для другого адреса добавьте `-HostIp 192.168.1.105`.
   Нужны Windows OpenSSH (`ssh`, `scp`), доступ `tusone` по SSH и право sudo.
   Установщик запросит пароли SSH/sudo штатно через `ssh -tt`.
   Файлы передаются с LF и UTF-8 без BOM; bash-код не передаётся heredoc из PowerShell.
3. Подключитесь:

   ```powershell
   ssh -tt tusone@192.168.1.105
   ```

4. В открытом Linux-терминале:

   ```bash
   nano ~/.config/slavik/.env
   ```

   Добавьте `GEMINI_API_KEY=ваш_ключ` (или `GOOGLE_API_KEY`).
   Это локальный файл с правами 600, не отправляйте его в чат.
   Старый `/root/.config/gemini-assistant/.env` автоматически не переносится.
   Если ключ содержит специальные символы shell, заключите значение в одинарные кавычки.

Приложение находится в `/home/tusone/slavik`, venv — в `~/slavik/.venv`.
Нужен Python >=3.11; SDK закреплён на наблюдавшейся версии 2.29.0.
Установщик ставит через apt инструменты сборки, Rust и Pulse-клиенты.
На ARMv7 pip может собирать зависимости из исходников: это может занять время
и потребовать больше памяти, чем доступно на плате. Сборка ограничена одним
потоком. Если установка остановилась, сохраните вывод ошибки: отключать TLS,
проверку подписей или менять версии наугад не нужно. ARM-установка здесь не проверена.

## Обновить существующую установку

Остановите агент через Ctrl+C, затем от tusone:

```bash
cd ~/slavik
git pull --ff-only
nano ~/.config/slavik/.env
# Задайте SLAVIK_WAKE_ENABLED=1 и SLAVIK_AWAKE_SECONDS=5
./start-gemini-assistant.sh --calibrate-mic
./start-gemini-assistant.sh
```

При локальных изменениях Git остановит обновление: не делайте reset --hard,
сначала сохраните изменения. Если в `.env` задан старый `GEMINI_SYSTEM_PROMPT`
с требованием молчать без имени, удалите эту строку или обновите инструкцию.

## Проверка и запуск — в Linux от tusone

```bash
cd ~/slavik
sudo -n -H -u voice /usr/local/libexec/slavik-audio check
./start-gemini-assistant.sh --audio-test
./start-gemini-assistant.sh --mic-test
./start-gemini-assistant.sh
```

Тесты звука/микрофона не требуют API-ключа и не подключаются к Gemini.
Звуковой тест отправляет 1 секунду тихого тона 440 Гц: услышать его нужно вам.
Микрофонный тест около 5 секунд выводит RMS/peak правого канала.
Проверьте, что уровень меняется при речи и нет постоянного clipping.
Если `check` не прошёл, проверьте уже существующие службы PipeWire/Pulse
пользователя `voice`. Установщик не меняет `voice-aec.conf`, микшер, I2S или службы.
Проверьте, что физическая колонка включена.

По умолчанию включён режим обращения. Скажите «Славик» или «Эй Славка»: затем
можно говорить без имени 5 секунд. Реплика в активном окне продлевает его.
После 5 секунд без реплик агент молчит до следующего обращения.
Проверьте повторное пробуждение и перебивание во время ответа.
`SLAVIK_WAKE_ENABLED=0` включает необязательный режим без обращения и таймера.
На умеренной громкости проверьте, что собственная речь не прерывает ассистента.
Ctrl+C или SIGTERM завершают сессию и аудиопроцессы. SSH-терминал остаётся
открытым во время работы; автозапуск Gemini не устанавливается. Отдельная
установка Spotify Connect создаёт службу slavik-spotify.

Для диагностики аудио:

```bash
DEBUG_AUDIO=1 ./start-gemini-assistant.sh
.venv/bin/python -m unittest discover -s tests -v
```

Ошибки SDK выводятся по типу/коду без полного ответа API и ключа.

## Калибровка микрофона

```bash
./start-gemini-assistant.sh --calibrate-mic
```

Остановите агент и музыку перед калибровкой. Первый этап — 3 секунды тишины
при обычном фоновом шуме. Второй — 10 секунд русской и английской речи с обычного
расстояния; нажмите Enter перед каждым этапом. Не кричите.
Отчёт показывает SNR, RMS речи/шума, clipping и рекомендуемое усиление.
Левый канал измеряется для сравнения, но вход остаётся правым, как в рабочей цепочке.
Профиль сохраняется в `~/.config/slavik/mic-calibration.json` с правами 600.
Аудиозапись не сохраняется. Плохой сигнал/аппаратная перегрузка не маскируются:
при недостаточной речи или clipping >0.5% новый профиль не записывается.

На входе всегда работает дешёвый high-pass 60 Гц против DC/низкого гула.
Усиление постоянное (0.25–4), по измеренной речи и запасу до перегрузки.
Пиковый ограничитель предотвращает добавленную цифровую перегрузку. Нет
шумового gate, подавления микрофона или агрессивного AGC, мешающего barge-in.
Усиление не восстанавливает речь, уже испорченную шумом или аппаратным clipping.
После калибровки сравните `--mic-test` и живую русскую/английскую речь.

`SLAVIK_MIC_GAIN` — ручной override 0.25..4; `SLAVIK_MIC_CALIBRATION` — путь профиля.
Удалите ручной override, если хотите использовать измеренное усиление.
Для отката профиля переместите его в резервную папку; без него gain=1,
high-pass остаётся. Не меняются ALSA mixer, sample rates и AEC-конфигурация.

## Доступ к звуку пользователя voice

Просто указать `PULSE_SERVER` пользователя `voice` в процессе `tusone`
недостаточно: Unix-сокет и каталог `/run/user/...` принадлежат другому пользователю.
Установщик создаёт root-owned `/usr/local/libexec/slavik-audio` и узкое правило
`/etc/sudoers.d/slavik-audio`: `tusone` может запускать этот помощник только от
`voice` для capture/playback/check. Это не запуск агента от root и не общий
доступ к sudo. Помощник принимает только режим и имя устройства, запускает
фиксированные `/usr/bin/parec`, `/usr/bin/pacat`, `/usr/bin/pactl`, определяет UID
`voice` динамически. SIGTERM помощнику убивает его текущий аудиопроцесс.
Работа этого пути через sudo и Pulse должна быть проверена на плате.

## Конфигурация

В `~/.config/slavik/.env` можно задать:

```bash
GEMINI_MODEL=gemini-3.1-flash-live-preview
GEMINI_VOICE=Kore
SLAVIK_WAKE_ENABLED=1
SLAVIK_AWAKE_SECONDS=5
GEMINI_MIC_SOURCE=voice_aec_source
GEMINI_SPEAKER_SINK=voice_aec_sink
DEBUG_AUDIO=0
SPOTIFY_ENABLED=0
```

`GEMINI_SYSTEM_PROMPT` — необязательная замена системной инструкции.
Не направляйте вывод мимо AEC sink: эхо-компенсация потеряет опорный сигнал.

## Spotify: от нуля до голосового воспроизведения

Нужен Spotify Premium. Добавлен собственный `spotify_api.py` на стандартной
библиотеке Python: поиск и запуск трека/исполнителя/плейлиста, pause/resume,
next/previous, volume ±10%. `radio` не реализовано и возвращает честный отказ.

1. Установите Connect-плеер на Banana Pi от tusone:

   ```bash
   cd ~/slavik
   bash install-spotify-connect.sh
   ```

   Используется официальный apt-репозиторий Raspotify с проверкой TLS и подписи
   пакетов. Требуется совместимый Debian/Armbian ARMv7 (armhf); upstream сейчас
   ориентирован на Debian 13. При несовместимости пакетов установка должна
   остановиться: не отключайте проверки или зависимости.
   Скрипт проверяет backend’ы командой `librespot --backend '?'`, а не через
   `--help`. При наличии pulseaudio использует его напрямую; иначе выбирает
   pipe и передаёт decoded PCM16 44.1 кГц stereo в pacat → voice_aec_sink.
   Пересборка librespot не нужна, если есть хотя бы pulseaudio или pipe.
   Root-owned помощник `/usr/local/libexec/slavik-spotify-player` следит за обоими
   процессами и завершает их при остановке службы. Временные файлы треков
   идут в writable `/run/slavik-spotify` (RuntimeDirectory, mode 0700),
   чтобы ProtectSystem=strict не блокировал запись в /tmp. Перед запуском
   проверяется создание временного файла. Pulse выполняет преобразование
   частоты музыкального потока для AEC; формат аудио Gemini не меняется.
   Он отключает пакетную службу raspotify и создаёт отдельную `slavik-spotify`
   от `voice`, выход — `voice_aec_sink`. Конфигурация Gemini/AEC не меняется.
   Музыка через Pulse попадает в тот же AEC reference; не выводите её напрямую ALSA.
   Политика/доступность стороннего Connect-клиента зависит от Spotify.

2. Откройте Spotify на телефоне в той же локальной сети. В списке устройств
   выберите **Slavik**, включите трек и проверьте звук. Connect должен сначала
   привязаться к вашему аккаунту. PID службы сам по себе не подтверждает готовность.

3. В [Spotify Developer Dashboard](https://developer.spotify.com/dashboard)
   создайте приложение с Web API. Redirect URI должен быть **точно**:
   `http://127.0.0.1:8888/callback`. Если Dashboard требует список разрешённых
   пользователей приложения, добавьте свой аккаунт. В `~/.config/slavik/.env`:

   ```bash
   SPOTIFY_CLIENT_ID=client_id_вашего_приложения
   SPOTIFY_DEVICE=Slavik
   SPOTIFY_ENABLED=1
   ```

   Client ID — идентификатор приложения; Client Secret не используется.
   Пароль аккаунта и токены не отправляйте в чат и не коммитьте в Git.

4. На Windows откройте SSH **с туннелем** (новое окно PowerShell):

   ```powershell
   ssh -tt -L 8888:127.0.0.1:8888 tusone@192.168.1.105
   ```

   В открытом Linux-терминале:

   ```bash
   cd ~/slavik
   ./start-gemini-assistant.sh --spotify-login
   ```

   Откройте показанную HTTPS-ссылку в браузере Windows и разрешите доступ.
   Callback пройдёт через SSH-туннель; сервер слушает только loopback.
   PKCE/S256 и state защищают авторизацию, окно входа действует 5 минут.
   Access/refresh tokens сохраняются локально с правами 600 и обновляются автоматически.

5. Проверьте и запустите:

   ```bash
   ./start-gemini-assistant.sh --spotify-status
   ./start-gemini-assistant.sh
   ```

   Скажите «Славик, включи песню ...», «Славик, пауза», «Славик, следующий трек».
   Команда выполняется только на устройстве `SPOTIFY_DEVICE`; случайный телефон
   или компьютер автоматически не выбирается. Успех означает принятую API-команду,
   слышимое воспроизведение подтвердите сами. HTTP 403/404/429 описываются как отказ.

Вызовы выполняются отдельной задачей, receive продолжает обрабатывать прерывания.
Команда из сна не выполняется. Команда, распознанная в активном окне, остаётся
разрешённой до окончания своего ответа, даже если Spotify отвечает дольше 5 секунд.
Уже начатое действие Spotify нельзя гарантированно отменить прерыванием речи.
Включение `SPOTIFY_ENABLED=1` без login не заменяет авторизацию.

Диагностика плеера:

```bash
sudo systemctl status slavik-spotify --no-pager
sudo journalctl -u slavik-spotify -n 50 --no-pager
```

Логи просмотрите локально; перед отправкой удалите любые данные авторизации.
Чтобы остановить Connect: `sudo systemctl disable --now slavik-spotify`.
Установка и реальное воспроизведение Spotify ещё требуют проверки на вашей плате.

## Почему так устроены звук, пробуждение и прерывание

- Одна успешная Live-сессия, непрерывный capture. `receive()` вызывается повторно
  после каждого хода, без открытия нового WebSocket. `proactivity` отсутствует.
- Вход: PCM16 16 кГц stereo из AEC source → правый канал mono.
- Выход: `response.data` в приоритете; inline PCM — запасной путь без дублирования.
  PCM16 mono 24 кГц → потоковая линейная интерполяция 48 кГц → одинаковые L/R.
  Сохраняются границы байтов и отсчётов между чанками. При конце хода выдаётся
  последний отсчёт. 1 секунда входного звука даёт ровно 1 секунду stereo-выхода.
- `interrupted` всегда очищает очередь, состояние ресемплера и процесс playback.
  Flush не ждёт блокировку writer/drain. Новая речь создаёт свежий playback.
  Микрофон никогда не выключается во время ответа; временного echo-guard нет.
  Остаток буфера физического устройства не измерен, поэтому абсолютную нулевую
  задержку прерывания не обещаем.
- LOW server VAD, prefix 320 мс и silence 500 мс сохранены из версии 05.
  AEC, расположение микрофона и громкость остаются критичными.
- По умолчанию ответы разрешены после обращения и до истечения окна ожидания
  команд. Таймер продлевается репликами только пока окно активно; обычная речь
  после его истечения не пробуждает ассистента. Включён дуплекс: микрофон
  передаёт звук и во время ответа.
  Сервер VAD всё равно отмечает начало/конец реплик для генерации ответа — это
  не остановка потока и не переподключение. Функция proactivity не добавлена.
- Русский/английский заданы в системной инструкции и ASR hints:
  `AudioTranscriptionConfig(language_codes=["ru-RU", "en-US"])` SDK 2.29.0.
  Это подсказки, не жёсткий фильтр языков: идеальное ограничение ASR не обещаем.
  При отказе сервера `Unknown name language_codes` только начальное подключение
  повторяется без поля; диалог между репликами не переподключается.
  `GEMINI_LANGUAGE_HINTS=0` вручную выключает поле. `proactivity` не добавляется.
  Ошибочную транскрипцию локально не подменяем; качество проверяется живой речью.
- Wake по умолчанию (`SLAVIK_WAKE_ENABLED=1`) — фильтр вывода по входной транскрипции, не локальная модель wake-word.
  Фоновый звук по-прежнему идёт в Gemini, может запускать VAD и расходует API.
  Фразы: «Эй Славка», «Славик», «Ебаные славики», «Славуха» с предусмотренными
  вариантами. Окно 5 секунд продлевается распознанной речью пользователя.
- В wake-режиме разрешение вывода фиксируется для каждого ответа. Уже разрешённый длинный
  ответ не обрезается по таймеру. Скрытый ответ никогда не выпускается позже:
  если wake-транскрипция пришла после начала ответа, этот ответ будет отброшен;
  повторите обращение. Это осознанный компромисс против воспроизведения старой речи.
- «Постоянная сессия» означает одну сессию между репликами, а не бесконечный
  срок WebSocket. При лимите сервера/разрыве агент завершается с очисткой;
  восстановление/резюмирование сессии в эту поставку не включено.

## Обновление и откат

Перед повторной установкой остановите работающий агент. PowerShell-установщик
сохраняет прежнюю папку `~/slavik` целиком в `~/slavik-backups/slavik-ДАТА-PID`.
Файл ключа вне папки приложения сохраняется. Старые инфраструктурные файлы
помощника и sudoers (если были) сохраняются в `~/slavik-backups/infrastructure-*`.
Не удаляйте резервные копии до проверки новой версии.

Для отката приложения от tusone, подставив конкретную резервную папку:

```bash
mv ~/slavik ~/slavik-failed-$(date +%Y%m%d-%H%M%S)
mv ~/slavik-backups/slavik-ДАТА-PID ~/slavik
cd ~/slavik
./start-gemini-assistant.sh
```

Для удаления впервые установленного аудиопомощника, после остановки агента:

```bash
sudo rm /etc/sudoers.d/slavik-audio
sudo rm /usr/local/libexec/slavik-audio
```

Если помощник/правило уже существовали, восстановите их из сохранённой
`infrastructure-*` папки через `sudo install` (helper: root:root 755,
sudoers: root:root 440), проверив правило через `sudo visudo -cf ПУТЬ`.
Существующий root-агент и настройки voice остаются как были.

## Голосовые команды, плейлисты и общая громкость

При обновлении остановите агента через Ctrl+C, затем:

```bash
cd ~/slavik
git pull --ff-only
bash install-linux.sh
bash install-spotify-connect.sh
```

Убавьте ручку колонки перед выставлением платы на максимум:

```bash
bash set-output-max.sh
```

Скрипт сохраняет ALSA и снимки Pulse, выставляет Headphone/Speaker в 0 dB,
Playback в 100% (0 dB), физический Pulse-выход в его base_volume и включает PCM.
На этой WM8960 прежние 100% Headphone/Speaker означали +6 dB, что могло ухудшать AEC.
Громкость `voice_aec_sink` сохраняется. Общие голосовые команды меняют
этот программный уровень, поэтому регулируются и музыка, и голос.
«Громче/тише» — шаг 10%, «громкость 40 процентов» — абсолютное значение.
Ручка колонки работает независимо. Spotify Connect начинает с громкости 100%;
громкость, выставленная отдельно в приложении Spotify, дополнительно влияет на музыку.

Примеры:

- «Славка, следующий трек» / «Предыдущий трек, Славка».
- «Славка, включи [название песни]».
- «Включи плейлист [название], Славка» — сначала ищется свой сохранённый плейлист.
- «Славка, включи третий трек из этого плейлиста».
- «Славка, включи [название песни] из этого плейлиста» — сохраняется очередь плейлиста.
- «Славка, включи грустную музыку» — Gemini выбирает запрос, Spotify ищет плейлист.
- «Славка, тише» / «Сделай громкость 40 процентов, Славка».

Для чтения закрытых и совместных плейлистов добавлены OAuth scopes.
Повторите `./start-gemini-assistant.sh --spotify-login` с тем же SSH-туннелем
и Redirect URI. Список песен чужого/редакционного плейлиста может быть
недоступен через Spotify API; в этом случае остаются next/previous и выбор по номеру.
Поиск по названию просматривает до 1000 позиций и просит уточнить неоднозначный запрос.

«Славка» теперь работает без «эй», в начале, середине и конце фразы.
Таймер бездействия остаётся 5 секунд. Для захвата начала речи установлены
500 мс предыстории и 700 мс тишины до завершения реплики.
RU/EN остаются подсказками распознавателю, а не строгим запретом других языков.
После настройки выхода повторите калибровку в тишине, с остановленной музыкой
и на обычном расстоянии до микрофона:

```bash
./start-gemini-assistant.sh --calibrate-mic
./start-gemini-assistant.sh --mic-test
./start-gemini-assistant.sh
```

Если имя неверно отображается в строке `Ты:`, пришлите несколько таких строк
вместе с результатом калибровки. Аудиозаписи и ключи для этой проверки не нужны.

## Диагностика обрывов и ручного переключения Spotify

Сначала остановите агент Ctrl+C, затем `git pull --ff-only`. Переустановка аудиомоста
для этих диагностических команд не требуется.

```bash
sudo -v
./start-gemini-assistant.sh --diagnose
```

Снимок показывает версии, CPU/RAM процессов (без аргументов запуска), состояние
службы, ALSA-микшер, Pulse-узлы/уровни/маршруты, аргументы AEC и профиль калибровки.
Он не запускает Gemini, не меняет уровни и не выводит .env/токены. Для Pulse используется
обычное право sudo пользователя tusone; `sudo -v` нужно выполнить в том же терминале.
Ошибки отдельных проверок не останавливают сбор остальных данных.
При включённом Spotify читается состояние API (при необходимости обновляется OAuth token).

При остановленном агенте выберите в приложении другой трек на Slavik и снимите:

```bash
./start-gemini-assistant.sh --spotify-status
./start-gemini-assistant.sh --spotify-next
./start-gemini-assistant.sh --spotify-status
sudo journalctl -u slavik-spotify --since '5 minutes ago' --no-pager
```

`--spotify-next` действительно отправляет команду переключения на устройство из
SPOTIFY_DEVICE; это проверка API, а не голосовой модели. Есть также --spotify-previous.
Статус показывает активное устройство, трек/контекст/позицию, repeat/shuffle и
запреты действий. Сравните, изменился ли URI трека и слышимая музыка. Если устройство
или API ограничивают команду, она вернёт ошибку вместо подтверждения воспроизведения.

Для обрывов без музыки остановите Spotify-воспроизведение кнопкой паузы и запустите:

```bash
SLAVIK_DEBUG_EVENTS=1 ./start-gemini-assistant.sh
```

Попросите короткий ответ и молчите до его окончания; затем отдельно проверьте
реальное перебивание. События показывают момент interruption, остаток очереди и
получение/выполнение команд инструментов. Снимок --diagnose во втором SSH-терминале
во время ответа покажет действующие sink-inputs/source-outputs. Печать событий
помогает сопоставить сбой, но сама по себе не измеряет эффективность AEC.

Если выбор любой песни запускает первую в плейлисте, включите ограниченный
debug Connect (перезапускает только slavik-spotify; кэш и авторизация сохраняются):

```bash
bash spotify-connect-debug.sh on
```

Заново выберите Slavik в приложении, включите плейлист и нажмите третью песню.
Затем проверьте явную позицию через API:

```bash
./start-gemini-assistant.sh --spotify-playlist-track 3
./start-gemini-assistant.sh --spotify-status
sudo journalctl -u slavik-spotify --since '3 minutes ago' --no-pager
```

Команда требует активный плейлист на выбранном устройстве и отправляет
context_uri с offset.position=2; она действительно меняет воспроизведение.
Журнал Connect содержит цели URI/UID/индекса, позволяя проверить fallback на 0.
Режим не включает подробные логи OAuth/session/dealer, но содержит музыкальный
контекст. После проверки выключите подробный журнал:

```bash
bash spotify-connect-debug.sh off
```

При таймауте API команда могла дойти до сервера. Сначала посмотрите статус;
автоматическое повторение next может переключить две песни вместо одной.

## Исправление выбора первой песни вместо выбранной в приложении

Подтверждённый журнал librespot 939dc5ee показал `Some(Uri(""))` и fallback на
позицию 0, тогда как API `Index(2)` успешно играл третью песню. Исправление в
PlayingTrack::try_from пропускает пустые URI/UID и использует следующий доступный
идентификатор. Патч и сборочные входы находятся в patches/ и vendor/librespot-armhf/.

После остановки Gemini:

```bash
cd ~/slavik
git pull --ff-only
bash install-connect-fix.sh
```

Скрипт для armhf проверяет контрольные суммы, исполняемый файл и Pulse backend,
сохраняет прежние локальные файлы и устанавливает отдельный плеер, сохраняя
пакетный /usr/bin/librespot. Заново выберите Slavik и нажмите три разные песни
в приложении. Если проверка прошла, выключите журнал: `bash spotify-connect-debug.sh off`.
Если снова выбирается первая, нужен новый журнал с `play track`/`Failed to resolve`:
пустой URI исправлен, но наличие правильного UID и его разрешение нужно подтвердить.

Откат на пакетный бинарник:

```bash
sudo mv /usr/local/libexec/slavik-librespot ~/slavik-backups/slavik-librespot-disabled
sudo systemctl restart slavik-spotify
```

Не запускайте install-connect-fix.sh на arm64/amd64: готовая сборка предназначена
для ARMv7 armhf. Звук/переключение на реальной плате подтверждает пользователь,
локальные тесты и проверка ELF не заменяют этого.


## Плохо слышит при Spotify: уровни и измерение AEC

Ручной выбор песен после Connect-патча подтверждён пользователем. Теперь отдельно
проверяем микрофон: в предыдущем снимке Capture был +30 dB, input boost +29 dB,
Headphone/Speaker +6 dB. Такой уровень может перегружать аналоговый тракт; цифровая
калибровка не устраняет искажения, уже возникшие до ADC. Это гипотеза по уровням,
а не доказательство причины всех ошибок ASR.

Остановите Славика через Ctrl+C, убавьте ручку колонки. Обновите код, затем:

```bash
cd ~/slavik
git pull --ff-only
bash tune-audio.sh
# Остановите музыку. Говорите с обычного расстояния, не вплотную к плате.
./start-gemini-assistant.sh --calibrate-mic
./start-gemini-assistant.sh --aec-test
```

`tune-audio.sh` сохраняет ALSA и Pulse в `~/slavik-backups/audio-*`, задаёт чистый
выход 0 dB, физический вход Pulse 80% и boost 20 dB. Общая громкость сохраняется.
Это начальная настройка конкретной WM8960; её эффективность нужно проверить на плате.
После изменения аппаратных уровней старый профиль калибровки использовать нельзя:
обязательно выполните калибровку заново. Если в `.env` задан `SLAVIK_MIC_GAIN`,
он имеет приоритет над профилем — уберите ручное переопределение для этого теста.

`--aec-test` не использует Gemini, не записывает аудиофайлы и не переключает каналы.
По приглашениям сначала измерьте тишину, затем музыку без речи, затем речь поверх
той же музыки. Музыку включайте именно на устройстве Slavik, громкость между двумя
последними этапами не меняйте. Тест печатает RMS, пики и клиппинг обоих каналов
до/после AEC. Для агента используется правый канал. Пришлите строку `AEC_REPORT=`.
RMS разных узлов нельзя напрямую считать величиной подавления эха: усиления
могут отличаться; важны также рост музыки над тишиной и сохранение вашей речи.

Затем попробуйте при умеренной громкости:

```bash
SLAVIK_DEBUG_EVENTS=1 ./start-gemini-assistant.sh
```

«Славик, включи Кизару», затем во время музыки «Славик, громкость десять».
Лог теперь показывает action/query инструмента. Кизару нормализуется в kizaru;
для play_artist требуется совпадение имени. Среди одноимённых артистов
используется число подписчиков/популярность, если API их возвращает, иначе порядок
релевантности Spotify; исполнитель с другим именем не включается. Результат поиска трека дополнительно содержит имя исполнителя.
RU/EN hints сохраняются, но серверное распознавание не гарантирует только эти языки.
Если тест покажет, что AEC убирает и вашу речь или почти не убирает музыку,
следующий шаг — настройка/маршрутизация AEC по измерениям, а не увеличение gain.


## Разговор поверх музыки: обновление аудиомоста

```bash
cd ~/slavik
git pull --ff-only
bash install-linux.sh
SLAVIK_DEBUG_EVENTS=1 ./start-gemini-assistant.sh
```

Переустановка аудиомоста нужна для команды `duck` и нового root-owned модуля
`/usr/local/libexec/music_duck.py`. Spotify приглушается примерно на 12 dB после
распознанного обращения, остаётся тише во время ответа и окна следующей команды.
После пяти секунд без речи/ответа восстанавливается прежняя громкость потока.
При обычном Ctrl+C она также восстанавливается; прямые изменения громкости
потока пользователем имеют приоритет. Общий master и громкость голоса не меняются.
Команды громкости по-прежнему управляют master, поэтому результат сохраняется
после снятия приглушения. В непрерывном режиме без wake музыка остаётся приглушённой;
`SLAVIK_MUSIC_DUCK=0` отключает это поведение.

Приглушение начинается только после распознавания обращения: оно облегчает дальнейший
разговор, но само по себе не исправляет распознавание первого имени при громкой музыке.
Небольшая задержка перед приглушением возможна. Пятисекундное окно теперь поддерживается
до окончания воспроизведения ответа и затем отсчитывается заново.

Для голоса запас Pulse-буфера увеличен с 40 до 120 мс. Это уменьшает чувствительность
к задержкам планировщика, но причина помех при смешивании ещё требует проверки на плате.
Для старого pipe-backend Spotify обновите также `bash install-spotify-connect.sh`:
поток pacat теперь имеет имя SlavikSpotify, позволяющее отличить его от голоса.
Текущая исправленная native Pulse-сборка librespot определяется по имени процесса.

«Слайк/Слайка» распознаются как обращение только вместе с приветствием или командой
(например, «Слайка, включи Кизару»). «Валик» и «слайды» не добавлены как обращения.
Это обработка наблюдаемых ошибок транскрипции, а не изменение акустического ASR.
Правый канал остаётся входом Gemini: произвольное усреднение микрофонов без выравнивания
их фазы/задержки может ухудшить речь. Для beamforming нужны характеристики массива.

Если Кизару всё ещё не найден, ошибка теперь содержит имена фактических результатов
Spotify. Предыдущая ошибка смешивала отсутствие совпадения с наличием нескольких
одноимённых артистов; второй случай теперь допускает выбор по ранжированию.


## Актуально: пробуждение по аудио и отдельная громкость голоса

Обычные «погромче/потише/громкость 20» теперь меняют только громкость Spotify.
«Славик, говори тише/громче», «громкость твоего голоса 30» меняют только голос.
Голос при каждом запуске начинается с 40% (цифровое масштабирование PCM); изменение
сохраняется до завершения процесса. Общий системный Pulse master остаётся фиксированным
в его текущем положении, программные команды его больше не трогают. Аппаратная ручка
колонки по-прежнему влияет на всё. Указания выше про общий master для голосовых команд
относятся к старой версии и заменены этим правилом.

Gemini слушает аудио непосредственно, и показанная транскрипция может не совпадать
с его пониманием. Теперь он может явно подтвердить услышанное обращение инструментом
`wake_assistant(addressed=true)`; это открывает окно и при ошибочном тексте имени.
В журнале появится `[Славик активирован по аудио]`. Обычный вызов музыкального инструмента
без обращения по-прежнему не открывает окно. Это распознавание обращения моделью,
не отдельный акустический keyword detector: ложные пробуждения ещё надо проверить
на живом шуме/песнях. Не добавлены общие алиасы «Валик», «Слава» и случайные слова.

Чтобы помогать уже первому обращению, после AEC отслеживается энергия правого канала:
не менее120мс выше RMS180 кратко приглушают музыку на две секунды с продлением во время
сигнала. Это лишь признак возможной речи, не точный VAD: другая речь или шум тоже могут
приглушать музыку, но никогда не разрешают команды и не будят агента. Тесты пользователя
дали остаток музыки RMS28.6 и речь с музыкой752.3, откуда выбран начальный порог180.
Один щелчок и постоянный DC не включают приглушение. При ложном приглушении нужен
дальнейший подбор по реальному аудио; `SLAVIK_MUSIC_DUCK=0` отключает приглушение целиком.

Обновление после предыдущей установки аудиомоста:

```bash
cd ~/slavik
git pull --ff-only
SLAVIK_DEBUG_EVENTS=1 ./start-gemini-assistant.sh
```

Проверьте при музыке обращение, затем «сделай потише», «говори громче»:
музыка и голос должны меняться независимо. Если предыдущий install-linux.sh ещё не
выполнялся после добавления duck, сначала выполните его. Повторная калибровка для
этого обновления не требуется: аппаратные уровни и аудиоформаты не менялись.


## Стабилизация после помех и посторонних фраз

Новый полевой лог показал перебивания и посторонние фразы после ответов. Это совместимо
с акустической обратной связью, но текст не доказывает её и не позволяет локализовать
помехи. Автоматическое приглушение (`SLAVIK_MUSIC_DUCK`), раннее приглушение
(`SLAVIK_EARLY_DUCK`) и модельное пробуждение (`SLAVIK_AUDIO_WAKE`) теперь по умолчанию
выключены (0). Для отдельного эксперимента флаги можно включить явно; основной путь
пока снова использует подтверждённое имя в транскрипции. Это откат нестабильных новых
механизмов, а не утверждение, что исправлена акустическая проблема распознавания имени.
Голос40% и независимое управление музыкой/голосом сохранены. Ответы по умолчанию
русские; переход на английский только по явной просьбе, согласно инструкции модели.

Следующее доказательство — запись во время сбоя. В первом SSH-окне запустите Славика,
во втором выполните:

```bash
cd ~/slavik
./start-gemini-assistant.sh --record-mic
```

За12сек записи произнесите обращение и вызовите ответ при музыке. Команда сохраняет
два локальных WAV в напечатанном каталоге `~/slavik-diagnostics/mic-*`:
`aec-before-dsp.wav` — правый канал после AEC до нашего DSP;
`sent-to-gemini.wav` — тот же захват после нашего DSP, в формате входа Gemini.
Запись явно включается только этой командой, никуда автоматически не отправляется;
файлы600, каталог700. Это отдельный клиент захвата с теми же настройками, а не
перехват websocket. Для анализа нужны оба файла и описание, что реально было сказано.
Если воспроизвести сбой не удалось, запись не доказывает отсутствие проблемы.


## Текущая политика приглушения и обрывы при действиях на плате

Пользователь требует приглушать музыку только после обращения и возвращать её
после диалога. Пока сохранено согласованное окно5сек после ответа. Теперь duck по
умолчанию включён, но требует отметки явного обращения и активного диалога; речь,
энергия микрофона и сам по себе непрерывный режим не включают его. Старый флаг
SLAVIK_EARLY_DUCK больше не действует на агента, анализ NearSpeech удалён из capture.
SLAVIK_MUSIC_DUCK=0 по-прежнему полностью отключает приглушение. Модельное пробуждение
по умолчанию выключено. Это заменяет прежние противоречащие описания политики выше.

Исправлен подтверждённый лишний сброс: server interrupted при пустой очереди и
завершённом выводе больше не закрывает pacat. Для активного ответа сохраняется

## Исправление рекомендации960 по исходникам PipeWire1.4.2

Отчёт пользователя на81b3c26 подтверждает QUANT960. ALSA input/output и AEC sink

Проверены upstream исходники именно1.4.2:
https://github.com/PipeWire/pipewire/blob/1.4.2/src/modules/module-echo-cancel.c
https://github.com/PipeWire/pipewire/blob/1.4.2/src/modules/module-protocol-pulse/modules/module-echo-cancel.c
process() берёт size=impl->aec_blocksize, отдаёт один блок playback и сбрасывает

Принудительный цикл960 при сохранении внутреннего блока480 не обеспечивает полный
выход на каждом цикле. Предыдущая гипотеза о достаточности кратности была неверной.

quantum480 (10мс), пересоздаёт Pulse/AEC через restart pipewire-pulse пользователяvoice,
проверяет появление AEC nodes и перезапускает slavik-spotify для подключения к новым
узлам. Музыка кратко прекращается. Системный PipeWire не рестартуется, metadata480
остаётся. Бывшие уровни/калибровка могут потребовать проверки после перезапуска Pulse;
намеренно не добавлены новые изменения микшера. Исходный force-quantum сохранён старым
backup-механизмом, audio-buffer.sh restore возвращает его. Не применять960/1024 с этим
AEC без одновременного изменения внутреннего размера блока или реализации модуля.

Приёмка ещё нужна: граф480, речь/музыка без роботизации и отсутствие роста ERR на
ВСЕХ узлах. Если на480 проявится нехватка времени, следующим шагом исправлять RT
доступ/планирование либо менять реализацию AEC с согласованным размером блока, а не
снова увеличивать только quantum. Ввод на50см ещё не оценён по WAV; усиление не трогать.

## Баланс громкости: голос громче музыки при Spotify100%

Возможен второй уровень: Pulse sink-input duck около-12dB отдельно от Spotify API.
Найдена уязвимость старого helper: сохранённая громкость была только в памяти, после
аварийного завершения оставалось занижение и следующий helper мог приглушить его снова.
Это механизм, а не доказанная причина конкретного случая — нужны фактические уровни.
Теперь voice-runtime/slavik-duck хранит исходные/применённые уровни до записи в Pulse,
восстанавливает подходящие потоки при новом запуске; flock запрещает второй duck-helper.
Идентичность потока и ручные изменения всё ещё проверяются перед восстановлением.
Старые занижения без журнала автоматически восстановить невозможно.

Голос40% теперь использует кубическую шкалу Pulse: gain=(percent/100)^3. Раньше gain=.4
давал-8dB при40%, теперь .064 (-24dB). Это изменение шкалы, а не замер акустической
громкости. Голос станет тише; «говори громче» меняет только голос. Музыка остаётся
под управлением Spotify, master/аналоговый микшер не меняются.

После остановки агента черезCtrl+C (музыку оставить): git pull; bash install-linux.sh
для нового root-owned music_duck.py; bash music-levels.sh reset. Последняя команда
показывает уровни, сохраняет backup и убирает только дополнительное ослабление
музыкальных Pulse-потоков, выставляя их100%/0dB. Spotify API volume, master и микрофон
не меняются. bash music-levels.sh безreset только показывает уровни.

Наблюдение пользователя: музыка наAEC подавляется хорошо при малой громкости, плохо
при большой, но речь остаётся различимой. Возможны нелинейность/перегрузка или
недостаточное подавление, но без WAV причина не установлена. Не усиливать микрофон
вслепую. Для оценки прослушать physical-stereo/aec-before-dsp/sent-to-gemini при
обоих уровнях; субъективная разборчивость человеком не гарантирует стабильный ASR.


## Двойное ослабление голоса: подтверждение по уровням

Пользователь после music-levels reset показал: music stream40% (-24.08dB)→100%,
voice_aec_sink всё ещё40% (-23.88dB), physical sink79% (-6dB/base соответствует0dB

примерно-48dB относительно цифрового unity. Это ошибка предыдущего разделения уровней,
а не доказанная неисправность микрофона.

Добавлен фиксированный prepare в root-owned slavik-audio и sudoers. Перед открытием
нового голосового потока старый master voice_aec_sink переносится пропорционально в

и сделает её громче. Уровень музыкального потока40% после миграции — допустим и не

облачной сессии нет поддерживаемого аудиовхода для прослушивания модели; не заявлять,
